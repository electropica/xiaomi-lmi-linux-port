# Activity previews contained in the drawer

Candidate drawerscroll4; not yet compiled or handset-qualified. The installed qualified version remains drawerscroll1. Drawerscroll2 and drawerscroll3 were rejected after the drawer/return gesture became inaccessible with Calculator open, and rolled back without reboot.

This candidate removes their page-notification visibility helpers. It starts from the accepted overview implementation and reparents its existing carousel into the applications page of the outer drawer before populating activities. The home page contains no previews. Mapping is controlled by HdyDeck itself; changing pages no longer removes/adds a sibling above the entire drawer. No gesture policy, home.c, compositor, battery policy or kernel changes are included.

The build input is the current drawerscroll3 source tree; the explicit rollback is drawerscroll1, never rejected versions 2 or 3. Three pinned files change: app-grid.c binds the page container, app-grid.ui gives that existing container an ID, overview.c reparents the existing carousel with an explicit reference during removal. Unchanged home/ESR files remain hash-pinned. Default preflight validates source/changelog state, rollback package metadata and scratch patch replay. Only operator --execute builds packages.

Evidence: a bounded invisible GTK 3/libhandy test ran on the handset without modifying Phosh or opening a visible window. Hiding the old sibling carousel moved the grid origin from 468 to 15 logical pixels, not zero. Therefore a zero-height drag handle is NOT an established cause. A second test loaded the actual candidate app-grid UI, replacing only its custom root type with GtkBox and removing signal handlers. It populated 38 application buttons, 16 home slots and five favorites, and exercised the proposed reparent sequence. Home/apps/home mapping, hidden-preview focus and grid geometry checks passed. The scroll upper/page values were 1291/169 in that small offscreen allocation. This is actual GTK layout validation, NOT production Phosh, compositor touch arbitration or complete C integration validation. No claim is made that it proves the observed failure's cause or guarantees the fix.

Acceptance after operator build and guarded installation: with Calculator open, bottom-edge return reaches home; home previews are absent; drawer opens with one and several windows and shows previews; list reaches its last row and returns to the top before a new downward gesture closes it; repeat open/close/launch; favorites and home drag/drop remain usable. Keep qualified drawerscroll1 rollback armed until all checks pass. Restart only the user Phosh service, never the full GNOME session service.
