# Home previews with settled drawer transitions

The installed, operator-accepted baseline is drawerscroll1: scroll to the first row before a new downward gesture closes the drawer. Drawerscroll2 was rejected because the application drawer became inaccessible. Its running-shell logs did not establish an assertion in the new callbacks. Rollback restored drawerscroll1 without reboot. A calculator-only check on that restored version remained responsive; version rollback and earlier window closures were initially confounded.

This candidate restores app-grid.c byte-for-byte to accepted drawerscroll1. It retains the requested hiding of running previews on home and showing them in the open drawer, but defers changes to carousel visibility while HdyDeck reports an active transition. A transition-running notification reconciles visibility after settling. No battery, compositor or kernel change is included.

This is a focused candidate, not a proven explanation of the prior failure. Changing both gesture directions and carousel allocation during page notification introduced two possible interference paths in the rejected variant; neither is claimed causally demonstrated by the available logs. Touch behavior still requires operator acceptance with windows open and closed.

The build tree currently contains drawerscroll2, so its two source hashes/changelog form the pinned build input. The NEW package is drawerscroll3, but rollback packages are explicitly drawerscroll1, the actual installed qualified baseline. A failed candidate must never restore rejected drawerscroll2. The recipe validates those distinct identities and compiles the Phosh tree once, producing a matched Phosh/common pair with package tests. --execute is operator-only; default preflight does not compile or contact the phone.

test-visibility-boundary.py replays the pinned patch in scratch and compiles the extracted production visibility helper with stub widgets. Sixteen combinations cover home/apps, running/settled transition, activities present/absent and previous visibility; the rejected helper control must fail for mutating visibility during a transition. These are real control-flow checks, not real GTK gesture validation. A separate GTK introspection import attempted inside the existing arm64 chroot stalled and was terminated; no passing graphical integration test is claimed.

Acceptance: home shows shortcuts/favorites without running previews; drawer opens with zero, one and multiple windows; previews appear only after opening; closing returns to home without previews; final row remains reachable; new downward gesture closes only after returning to the top; launch/close apps and home icon drag/drop remain usable. Keep rollback to drawerscroll1 armed until those checks pass. Installation restarts only the user Phosh shell.
